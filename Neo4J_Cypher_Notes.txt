

Neo4j is a graph database management system designed to store and manage connected data using nodes, relationships, and properties.

Cypher is the declarative query language used to create, read, update, and search data stored inside Neo4j.

Node: The primary data entity in a graph that represents an object, person, or concept (like a record or table row).
Property: A key-value pair stored inside a node or relationship to hold descriptive data attributes.
Relationship: A directed, named connection that links two nodes together to represent how they are associated.






--------------------------Data types in cypher----------------------------
1.String: text ("yagnesh",'smit')
2.Integer:Whole numbers
3.Float:floating number [1.92,2.3]
4.Boolean:(true,false)
5.List: Ordered collection of values (['Lakers', 'Clippers', 'Nuggets'],["yagnesh", 0, true, 3.9]).
6.Map: Key-value pairs ({team: 'Clippers', active: true}).
7.Date / Time: Temporal values using ISO 8601 formatting (date('2026-08-31'), datetime(), duration('P1Y')).

ACID compliance
Neo4j is fully ACID compliant. This means that:

Atomicity - If a part of a transaction fails, the database state is left unchanged.

Consistency — Every transaction leaves the database in a consistent state.

Isolation — During a transaction, modified data cannot be accessed by other operations.

Durability — The DBMS can always recover the results of a committed transaction.

What is Aura?
Aura is Neo4j’s fully managed cloud service. It consists of AuraDB and AuraDS. AuraDB is a graph database service for developers building intelligent applications, and AuraDS is a Graph Data Science (GDS) service for data scientists building predictive models and analytics workflows.



The data entities in a Neo4j graph database are called nodes. Nodes are referred to in Cypher using parentheses ().

Nodes in a graph can be connected with relationships. A relationship must have a start node, an end node, and exactly one type. Relationships are represented in Cypher with arrows (e.g. -->) indicating the direction of a relationship.
Unlike nodes, information within a relationship pattern must be enclosed by square brackets.


Paths in a graph consist of connected nodes and relationships. Exploring these paths sits at the very core of Cypher.
MATCH p = SHORTEST 1 (:Person {name: 'Anna'})-[:KNOWS]-+(:Person {nationality: 'Canadian'})RETURN p

	Finding connected nodes
	To discover how nodes are connected to one another, relationships must be added to queries. Queries can specify relationship types, properties, and direction, as well as the start and end nodes of the pattern.
	match(m:Movie{title:"The Matrix"})<-[d:DIRECTED]-(p:Person) return p as person;
	
	
	
	match(tom:Person{name:"Tom Hanks"})-[r]->(m:Movie) RETURN type(r) as type,m.title as movie;
	
	MATCH (:Person {name:'Tom Hanks'})-[r:!ACTED_IN]->(m:Movie)Return type(r) AS type, m.title AS movies
	
	
To search for patterns of a fixed length, specify the distance (hops) between the nodes in the pattern by using a quantifier ({n}). For example, the following query matches all Person nodes exactly 2 hops away from Tom Hanks and returns the first five rows. The `DISTINCT operator ensures that the result contain no duplicate values.





The SHORTEST keyword can be used to find a variation of the shortest paths between two nodes. In this example, ALL SHORTEST paths between the two nodes Keanu Reeves and Tom Cruise are found. The count() function calculates the number of these shortest paths while the length() function calculates the length of each path in terms of traversed relationships.
MATCH p = ALL SHORTEST (:Person {name:"Keanu Reeves"})--+(:Person {name:"Tom Cruise"})
RETURN count(p) AS pathCount, length(p) AS pathLength
